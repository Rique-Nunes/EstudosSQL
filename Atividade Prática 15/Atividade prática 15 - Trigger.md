# **Triggers no Oracle Database: Conceitos, Arquitetura e Roteiro Prático no Oracle APEX**

# **1\. Fundamentos Teóricos: O que é uma Trigger?**

## **Definição e Propósito**

Um gatilho (*Trigger*) é um bloco PL/SQL nomeado associado a uma tabela, view ou evento do sistema, disparado (executado) de forma automática e implícita pelo Oracle Database quando um evento específico ocorre (DML, DDL ou eventos de banco/sessão).

## **Classificação e Níveis de Disparo**

### **Timing (Momento de Disparo)**

* **`BEFORE`**: Executado antes da operação DML ser aplicada aos dados físicos da tabela. Ideal para validações, higienização, derivação de valores e regras impeditivas.  
* **`AFTER`**: Executado após a operação DML ter sido aplicada no banco de dados. Ideal para auditoria, replicação e geração de logs históricos.  
* **`INSTEAD OF`**: Utilizado primordialmente sobre Views complexas não atualizáveis, interceptando comandos DML e redirecionando as operações para as tabelas base subjacentes.

### **Nível de Execução**

* **Statement-Level Trigger (Nível de Instrução)**: Dispara apenas uma única vez para o comando SQL como um todo, independentemente de quantas linhas foram afetadas (mesmo se zero linhas forem modificadas). É o comportamento padrão quando a cláusula `FOR EACH ROW` é omitida.  
* **Row-Level Trigger (Nível de Linha)**: Declarada com a cláusula `FOR EACH ROW`. Dispara individualmente para cada linha inserida, alterada ou excluída pela instrução DML.

## **Identificadores de Correlação (Pseudorow / Pseudoregistros)**

* **`:NEW`**: Contém os novos valores que estão sendo gravados ou atualizados no registro. Disponível em operações `INSERT` e `UPDATE`.  
* **`:OLD`**: Contém os valores originais existentes no registro antes da alteração ou exclusão. Disponível em operações `UPDATE` e `DELETE`.

| Operação DML | Pseudoregistro :OLD | Pseudoregistro :NEW |
| :---- | :---- | :---- |
| **`INSERT`** | `NULL` | Contém os novos valores inseridos |
| **`UPDATE`** | Contém os dados anteriores à alteração | Contém os novos dados propostos |
| **`DELETE`** | Contém os dados removidos | `NULL` |

## **Predicados Condicionais**

Permitem unificar lógicas multi-DML em um único gatilho através das variáveis booleanas:

* `INSERTING`: Retorna `TRUE` se o evento disparador for uma instrução `INSERT`.  
* `UPDATING`: Retorna `TRUE` se o evento disparador for uma instrução `UPDATE`.  
* `DELETING`: Retorna `TRUE` se o evento disparador for uma instrução `DELETE`.

## **A Cláusula WHEN**

Permite condicionar a execução de um gatilho em nível de linha sem despender recursos do mecanismo de execução do corpo PL/SQL. A validação é avaliada antes do contexto PL/SQL ser inicializado.

## **O Fenômeno da Tabela Mutante (ORA-04091: table is mutating)**

* **Causa Física**: Ocorre quando um Row-Level Trigger tenta consultar (`SELECT`) ou modificar (`DML`) a própria tabela que disparou a execução enquanto ela ainda está sendo processada no contexto da transação.  
* **Soluções de Arquitetura**: Uso de *Compound Triggers* (recurso introduzido no Oracle 11g), variáveis de sessão em pacotes (*Package Variables*) ou transferência da lógica de validação para procedimentos de serviço no nível da aplicação.

## **Etapa 1: Criação do Esquema Base (Funcionários e Auditoria Transacional)**

Criar as tabelas base para simular o controle cadastral e a trilha de auditoria:

```
-- 1. Tabela Principal de Colaboradores
CREATE TABLE tb_empregados (
    id_empregado   NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome           VARCHAR2(100) NOT NULL,
    cargo          VARCHAR2(50) NOT NULL,
    salario        NUMBER(10,2) NOT NULL,
    status         VARCHAR2(20) DEFAULT 'ATIVO' NOT NULL,
    data_criacao   DATE DEFAULT SYSDATE
);

-- 2. Tabela de Trilha de Auditoria (Audit Log)
CREATE TABLE tb_auditoria_salarios (
    id_audit         NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_empregado     NUMBER NOT NULL,
    operacao         VARCHAR2(10) NOT NULL, -- 'INSERT', 'UPDATE', 'DELETE'
    salario_anterior NUMBER(10,2),
    salario_novo     NUMBER(10,2),
    usuario_db       VARCHAR2(50) DEFAULT USER,
    data_evento      TIMESTAMP DEFAULT SYSTIMESTAMP
);

-- 3. Carga Inicial de Dados
INSERT INTO tb_empregados (nome, cargo, salario) VALUES ('Ana Beatriz Costa', 'ANALISTA PL', 5200.00);
INSERT INTO tb_empregados (nome, cargo, salario) VALUES ('Lucas Albuquerque', 'DESENVOLVEDOR SR', 9800.00);
INSERT INTO tb_empregados (nome, cargo, salario) VALUES ('Mariana Silveira', 'COORDENADORA TI', 12500.00);
COMMIT;
```

## **Etapa 2: Criação de Trigger BEFORE Row-Level (Validação e Higienização de Dados)**

Implementar um gatilho que valide regras rígidas de negócio (impedir redução de salário e padronizar campos em maiúsculas):

```
CREATE OR REPLACE TRIGGER trg_empregados_biu_valida
BEFORE INSERT OR UPDATE ON tb_empregados
FOR EACH ROW
BEGIN
    -- 1. Higienização: Forçar campos textuais em maiúsculas
    :NEW.nome  := UPPER(TRIM(:NEW.nome));
    :NEW.cargo := UPPER(TRIM(:NEW.cargo));

    -- 2. Regra de Negócio: Salário não pode ser menor que o salário mínimo nacional (R$ 1.412,00)
    IF :NEW.salario < 1412.00 THEN
        RAISE_APPLICATION_ERROR(-20001, 'Violação: O salário informado não pode ser inferior ao piso da categoria.');
    END IF;

    -- 3. Regra de Negócio: Em operações de UPDATE, impedir redução arbitrária de remuneração
    IF UPDATING THEN
        IF :NEW.salario < :OLD.salario THEN
            RAISE_APPLICATION_ERROR(-20002, 'Violação: Não é permitida a redução nominal do salário de um colaborador ativo.');
        END IF;
    END IF;
END trg_empregados_biu_valida;
/
```

## **Etapa 3: Criação de Trigger AFTER Row-Level (Trilha de Auditoria Histórica)**

Implementar um gatilho que grave automaticamente alterações na tabela de auditoria:

```
CREATE OR REPLACE TRIGGER trg_empregados_auditoria
AFTER INSERT OR UPDATE OR DELETE ON tb_empregados
FOR EACH ROW
BEGIN
    IF INSERTING THEN
        INSERT INTO tb_auditoria_salarios (id_empregado, operacao, salario_anterior, salario_novo)
        VALUES (:NEW.id_empregado, 'INSERT', NULL, :NEW.salario);
    ELSIF UPDATING THEN
        -- Só grava auditoria se o salário realmente foi alterado
        IF :NEW.salario <> :OLD.salario THEN
            INSERT INTO tb_auditoria_salarios (id_empregado, operacao, salario_anterior, salario_novo)
            VALUES (:OLD.id_empregado, 'UPDATE', :OLD.salario, :NEW.salario);
        END IF;
    ELSIF DELETING THEN
        INSERT INTO tb_auditoria_salarios (id_empregado, operacao, salario_anterior, salario_novo)
        VALUES (:OLD.id_empregado, 'DELETE', :OLD.salario, NULL);
    END IF;
END trg_empregados_auditoria;
/
```

## **Etapa 4: Criação de Trigger BEFORE Statement-Level (Controle de Janela de Manutenção)**

Implementar um gatilho em nível de instrução que bloqueie alterações fora do horário permitido ou fins de semana:

```
CREATE OR REPLACE TRIGGER trg_bloqueio_fim_semana
BEFORE DELETE ON tb_empregados
DECLARE
    v_dia_semana VARCHAR2(20);
BEGIN
    -- Obtém o dia da semana formatado
    v_dia_semana := TO_CHAR(SYSDATE, 'DY', 'NLS_DATE_LANGUAGE=ENGLISH');

    -- Bloqueia exclusões no sábado ou domingo
    IF v_dia_semana IN ('SAT', 'SUN') THEN
        RAISE_APPLICATION_ERROR(-20005, 'Operações de exclusão de dados são proibidas durante finais de semana.');
    END IF;
END trg_bloqueio_fim_semana;
/
```

## **Etapa 6: Consulta, Manutenção e Auditoria no Dicionário de Dados**

WHERE table_name = 'TB_EMPREGADOS'

# **4\. Checklist de Boas Práticas e Arquitetura de Banco de Dados**

* **Uso Criterioso**: Triggers executam de forma transparente e implícita; seu excesso dificulta a depuração (*debugging*) de sistemas transacionais complexos.  
* **Não Confundir com Regras Declarativas**: Sempre prefira restrições declarativas (`NOT NULL`, `CHECK`, `UNIQUE`, `FOREIGN KEY`) antes de recorrer a triggers para validações simples.  
* **Atenção ao ORA-04091**: Nunca faça consultas à tabela que acionou o gatilho dentro de um *Row-Level Trigger*.  
* **Tratamento de Exceções**: Se um trigger lançar uma exceção não tratada, toda a instrução DML chamadora é imediatamente abortada e revertida.
