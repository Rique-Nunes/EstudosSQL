# **Stored Procedures no Oracle Database: Conceitos, Arquitetura e Roteiro Prático no Oracle APEX**

# **1\. Fundamentos Teóricos: O que é uma Stored Procedure?**

## **Definição e Propósito**

Uma **Stored Procedure** é um bloco PL/SQL nomeado, compilado e armazenado diretamente no repositório de dados (*Data Dictionary*) do servidor Oracle Database. Seu objetivo primário é encapsular uma sequência de instruções procedurais e comandos de manipulação de dados (DML/TCL), permitindo a execução de regras de negócio complexas com alto nível de abstração e eficiência.

## **Vantagens Arquiteturais**

* **Desempenho e Redução do Tráfego de Rede**: Elimina múltiplos ciclos de ida e volta (*round-trips*) entre a aplicação cliente e o servidor. Uma única chamada pela rede dispara a execução de centenas de comandos internamente no banco de dados.  
* **Manutenibilidade e Centralização da Regra de Negócio**: Impede a duplicação de regras em diferentes camadas ou linguagens (Java, Python, C\#, APEX). Alterações na lógica de negócio exigem manutenção apenas no banco de dados, propagando-se instantaneamente para todos os consumidores.  
* **Segurança e Camada de Abstração de Privilégios**: Permite a concessão do privilégio `EXECUTE` sem a necessidade de conceder permissões diretas de `SELECT`, `INSERT`, `UPDATE` ou `DELETE` nas tabelas subjacentes aos usuários finais (mecanismo *Authid Definer* vs *Authid Current\_User*).  
* **Recompilação e Otimização em Cache**: O código-fonte é pré-compilado em uma representação intermediária (*p-code*) armazenada na *Shared Pool* (*Library Cache*). Isso permite o reuso contínuo do plano de execução por múltiplas sessões simultâneas, otimizando o uso de CPU e memória.

## **Anatomia Estrutural de uma Procedure**

Uma Stored Procedure no Oracle é constituída por quatro seções principais:

1. **Cabeçalho**: Define o nome do objeto, modificadores de criação (`CREATE OR REPLACE`) e a lista de parâmetros de entrada/saída.  
2. **Seção Declarativa**: Compreendida entre o cabeçalho e a palavra `BEGIN`. Reservada para declaração de variáveis locais, tipos de dados, constantes e cursores. *Não utiliza a palavra DECLARE*.  
3. **Seção Executável**: Iniciada por `BEGIN` e finalizada por `END`. Contém as instruções de controle de fluxo, atribuições de variáveis e comandos SQL.  
4. **Seção de Tratamento de Exceções**: Delimitada por `EXCEPTION`, intercepta erros em tempo de execução para permitir tratamento gracioso e consistência transacional.

## **Modos de Parâmetros**

| Modo | Direção | Comportamento e Características |
| :---- | :---- | :---- |
| `IN` | Entrada | Modo padrão. Passado por valor (ou referência via `NOCOPY`). O parâmetro comporta-se como uma constante somente leitura dentro do bloco e não pode receber atribuições. |
| `OUT` | Saída | O valor inicial retornado pela sessão é ignorado. A procedure atribui um novo valor à variável durante ou ao final da execução, retornando-o para a aplicação chamadora. |
| `IN OUT` | Bidirecional | Recebe um valor inicial da sessão chamadora, permite leitura e alteração do conteúdo internamente, e devolve o valor modificado ao término do bloco. |

## **Comparativo: Procedure vs Function**

| Critério | Stored Procedure | Stored Function |
| :---- | :---- | :---- |
| **Propósito Principal** | Executar ações, transformações e controle transacional. | Calcular e retornar um valor específico. |
| **Retorno de Valores** | Não possui cláusula `RETURN` obrigatória; devolve dados via parâmetros `OUT`/`IN OUT`. | Deve conter obrigatoriamente a cláusula `RETURN` no cabeçalho e corpo. |
| **Uso em Comandos SQL** | Não pode ser chamada diretamente em instruções `SELECT`, `WHERE` ou `INSERT`. | Pode ser invocada diretamente em consultas SQL (se não violar níveis de pureza). |

## **Etapa 1: Criação do Esquema Base**

Criaremos o modelo de dados para um sistema financeiro simplificado, contendo a tabela de contas correntes e a tabela de log de movimentações.

```
-- 1. Tabela de Contas Correntes
CREATE TABLE tb_contas (
    id_conta     NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    titular      VARCHAR2(100) NOT NULL,
    saldo        NUMBER(12,2) DEFAULT 0 NOT NULL,
    status       VARCHAR2(10) DEFAULT 'ATIVA' CHECK (status IN ('ATIVA', 'BLOQUEADA'))
);

-- 2. Tabela de Extrato / Log de Movimentações
CREATE TABLE tb_movimentacoes (
    id_movimento    NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_conta_origem NUMBER REFERENCES tb_contas(id_conta),
    id_conta_dest   NUMBER REFERENCES tb_contas(id_conta),
    tipo_operacao   VARCHAR2(20) NOT NULL,
    valor           NUMBER(12,2) NOT NULL,
    data_movimento  DATE DEFAULT SYSDATE NOT NULL
);

-- 3. Carga Inicial de Dados
INSERT INTO tb_contas (titular, saldo, status) VALUES ('Alexandre Louzada', 5000.00, 'ATIVA');
INSERT INTO tb_contas (titular, saldo, status) VALUES ('Empresa Tech Solutions', 12000.00, 'ATIVA');
INSERT INTO tb_contas (titular, saldo, status) VALUES ('Conta Bloqueada Teste', 1500.00, 'BLOQUEADA');
COMMIT;
```

## **Etapa 2: Procedure com Parâmetros IN e OUT (Depósito Validado)**

Nesta etapa, criamos uma procedure responsável por processar depósitos. Ela executa validações de negócio e devolve o novo saldo e a mensagem de status via parâmetros `OUT`.

```
CREATE OR REPLACE PROCEDURE prc_realizar_deposito (
    p_id_conta    IN  NUMBER,
    p_valor       IN  NUMBER,
    p_novo_saldo  OUT NUMBER,
    p_status_msg  OUT VARCHAR2
) IS
    v_status_conta VARCHAR2(10);
BEGIN
    -- Validação de valor positivo
    IF p_valor <= 0 THEN
        p_status_msg := 'ERRO: O valor do depósito deve ser maior que zero.';
        p_novo_saldo := NULL;
        RETURN;
    END IF;

    -- Verificar status da conta
    SELECT status, saldo INTO v_status_conta, p_novo_saldo
    FROM tb_contas
    WHERE id_conta = p_id_conta;

    IF v_status_conta <> 'ATIVA' THEN
        p_status_msg := 'ERRO: A conta está bloqueada ou inativa.';
        p_novo_saldo := NULL;
        RETURN;
    END IF;

    -- Atualizar saldo
    UPDATE tb_contas
    SET saldo = saldo + p_valor
    WHERE id_conta = p_id_conta
    RETURNING saldo INTO p_novo_saldo;

    -- Registrar movimentação
    INSERT INTO tb_movimentacoes (id_conta_dest, tipo_operacao, valor)
    VALUES (p_id_conta, 'DEPOSITO', p_valor);

    COMMIT;
    p_status_msg := 'SUCESSO: Depósito efetuado com êxito.';

EXCEPTION
    WHEN NO_DATA_FOUND THEN
        p_status_msg := 'ERRO: Conta inexistente.';
        p_novo_saldo := NULL;
        ROLLBACK;
    WHEN OTHERS THEN
        p_status_msg := 'ERRO INESPERADO: ' || SQLERRM;
        p_novo_saldo := NULL;
        ROLLBACK;
END prc_realizar_deposito;
/
```

## **Etapa 3: Execução e Inspecção no SQL Commands**

Para executar uma procedure com parâmetros `OUT` no SQL Commands do APEX, utiliza-se um bloco anônimo PL/SQL e o pacote `DBMS_OUTPUT` para visualização dos resultados.

```
DECLARE
    v_saldo_atual NUMBER;
    v_mensagem    VARCHAR2(200);
BEGIN
    -- Chamada da procedure passando a conta 1 e valor 1500
    prc_realizar_deposito(
        p_id_conta   => 1,
        p_valor      => 1500.00,
        p_novo_saldo => v_saldo_atual,
        p_status_msg => v_mensagem
    );

    DBMS_OUTPUT.PUT_LINE('Resultado: ' || v_mensagem);
    DBMS_OUTPUT.PUT_LINE('Novo Saldo: R$ ' || TO_CHAR(v_saldo_atual, 'FM999G999D00'));
END;
/
```

## **Etapa 4: Procedure Transacional Completa (Transferência Bancária)**

Esta procedure gerencia a transferência de fundos entre duas contas. Ela emprega a cláusula `FOR UPDATE` para garantir o controle de concorrência, exceções customizadas e gerenciamento transacional estrito (`COMMIT`/`ROLLBACK`).

```
CREATE OR REPLACE PROCEDURE prc_transferir_fundos (
    p_origem  IN NUMBER,
    p_destino IN NUMBER,
    p_valor   IN NUMBER
) IS
    v_saldo_origem NUMBER;
    v_status_orig  VARCHAR2(10);
    v_status_dest  VARCHAR2(10);
    e_saldo_insuficiente EXCEPTION;
    e_conta_bloqueada    EXCEPTION;
BEGIN
    -- Validar valor
    IF p_valor <= 0 THEN
        RAISE_APPLICATION_ERROR(-20001, 'Valor de transferência inválido.');
    END IF;

    -- Bloquear e verificar conta de origem (SELECT FOR UPDATE evita concorrência)
    SELECT saldo, status INTO v_saldo_origem, v_status_orig
    FROM tb_contas
    WHERE id_conta = p_origem
    FOR UPDATE;

    IF v_status_orig <> 'ATIVA' THEN
        RAISE e_conta_bloqueada;
    END IF;

    IF v_saldo_origem < p_valor THEN
        RAISE e_saldo_insuficiente;
    END IF;

    -- Verificar conta de destino
    SELECT status INTO v_status_dest
    FROM tb_contas
    WHERE id_conta = p_destino;

    IF v_status_dest <> 'ATIVA' THEN
        RAISE e_conta_bloqueada;
    END IF;

    -- Debitar da conta de origem
    UPDATE tb_contas SET saldo = saldo - p_valor WHERE id_conta = p_origem;

    -- Creditar na conta de destino
    UPDATE tb_contas SET saldo = saldo + p_valor WHERE id_conta = p_destino;

    -- Registrar transação no extrato
    INSERT INTO tb_movimentacoes (id_conta_origem, id_conta_dest, tipo_operacao, valor)
    VALUES (p_origem, p_destino, 'TRANSFERENCIA', p_valor);

    -- Confirmar transação atomicamente
    COMMIT;
    DBMS_OUTPUT.PUT_LINE('Transferência de R$ ' || p_valor || ' concluída com sucesso.');

EXCEPTION
    WHEN e_saldo_insuficiente THEN
        ROLLBACK;
        RAISE_APPLICATION_ERROR(-20002, 'Falha: Saldo insuficiente na conta de origem.');
    WHEN e_conta_bloqueada THEN
        ROLLBACK;
        RAISE_APPLICATION_ERROR(-20003, 'Falha: Uma das contas envolvidas está bloqueada.');
    WHEN NO_DATA_FOUND THEN
        ROLLBACK;
        RAISE_APPLICATION_ERROR(-20004, 'Falha: Conta de origem ou destino não localizada.');
    WHEN OTHERS THEN
        ROLLBACK;
        RAISE_APPLICATION_ERROR(-20099, 'Erro inesperado na transferência: ' || SQLERRM);
END prc_transferir_fundos;
/
```

## **Etapa 6: Consulta e Auditoria no Dicionário de Dados**

O banco de dados Oracle disponibiliza exibições (*views*) de catálogo para inspecionar a estrutura, o status e o código-fonte de programas armazenados:

```
-- Consultar procedures existentes no schema
SELECT object_name, object_type, status, last_ddl_time
FROM user_objects
WHERE object_type = 'PROCEDURE'
ORDER BY object_name;

-- Consultar erros de compilação de código PL/SQL
SELECT name, type, line, position, text
FROM user_errors
WHERE type = 'PROCEDURE'
ORDER BY sequence;

-- Consultar o código fonte armazenado no banco
SELECT line, text
FROM user_source
WHERE name = 'PRC_TRANSFERIR_FUNDOS'
ORDER BY line;
```

# **4\. Checklist de Boas Práticas e Arquitetura PL/SQL**

* **Tratamento de Exceções Rigoroso**: Sempre capture erros potenciais e force a execução do `ROLLBACK` nos blocos de exceção para prevenir a manutenção de travas (*locks*) não intencionais na sessão.  
* **Controle de Concorrência**: Utilize a sintaxe `SELECT ... FOR UPDATE` ao realizar a leitura de dados que serão modificados na sequência da transação, evitando condições de corrida (*race conditions*).  
* **Princípio da Responsabilidade Única**: Mantenha as Stored Procedures focadas em um objetivo claro e bem delimitado. Evite construir procedures monolíticas que executem rotinas não correlacionadas.  
* **Modularização via Packages**: Em ambientes de produção, agrupe procedures e funções correlatas dentro de **Packages** (Especificação e Corpo). Isso otimiza o carregamento em memória, melhora a organização de namespace e permite o uso de variáveis e métodos privados.
